# 案例教研优化需求说明书

> 本文档为 V1.0 历史版本，包含已废止的线性流程与成果依赖规则。开发实施请使用 [《案例教研增量改造需求说明 V2.0》](./案例教研增量改造需求说明_V2.0.md)。

版本：V1.0  
日期：2026-07-30  
适用对象：产品经理、交互设计、前端开发、后端开发、测试人员  
原型技术：Vue 3 + Vite + Element Plus

## 1. 项目背景

现有案例教研已经覆盖教研准备和教研成果，但缺少教研过程的线上沉淀。新版在保留主题生成、活动方案、案例小结和整次教研总结的基础上，增加类似 BBS 的话题与回复能力，并补齐线下会议资料、AI 会议纪要和完整资料归档。

本轮优化重点不是新增独立业务模块，而是将现有能力整理为一条状态明确、权限清晰、管理端和教师端都容易理解的教研闭环。

## 2. 产品目标

1. 用话题与回复记录线上研讨过程。
2. 用录音、转写稿、AI 会议纪要和附件记录线下会议过程。
3. 一次教研支持多个关联案例，每个案例独立形成案例小结。
4. 全部案例小结完成后，汇总形成一份整次教研总结。
5. 将主题资料、会议资料、小结和总结统一压缩归档，不再生成教研报告。
6. 管理端与教师端使用同一条业务状态，列表进度与详情进度保持一致。
7. 权限按教师、教研范围和教研内角色组合控制，不与其他业务模块权限绑定。

## 3. 用户角色

### 3.1 管理端

适用角色包括园级管理员、教研负责人和本次教研主持人。可在授权范围内创建、编辑、发布、结束教研，预设话题，管理成员，上传会议资料，生成 AI 会议纪要，生成案例小结、教研总结和归档包。

### 3.2 普通教师

普通教师只看到三个业务入口：

1. 教研主题。
2. 在线研讨。
3. 成果文件。

普通教师可在授权范围内查看主题、加入教研、发表话题、回复观点、查看已发布的案例小结和教研总结。普通教师不进入现场记录页面，不上传或修改管理归档资料。

## 4. 教研生命周期

系统统一使用四个阶段：

1. 教研准备。
2. 在线研讨。
3. 现场记录。
4. 成果沉淀。

“教研召开”不再作为系统流程节点。线下会议是实际业务事件，发生在“在线研讨”结束与“现场记录”开始之间。主持人在线下会议结束后点击“结束教研”，系统直接进入现场记录。

### 4.1 状态与阶段映射

| 业务状态 | 阶段 | 说明 | 建议进度 |
|---|---|---|---:|
| 草稿 | 教研准备 | 仅创建人和管理者可见 | 0%-40% |
| 研讨中 | 在线研讨 | 已发布，可发表话题和回复；线下会议未结束 | 40%-75% |
| 现场记录 | 现场记录 | 线下会议已结束，正在整理资料 | 75%-90% |
| 待总结 | 成果沉淀 | 现场资料已确认，正在生成小结和总结 | 90%-99% |
| 已完成 | 成果沉淀 | 归档包已生成 | 100% |

状态、阶段和进度必须存储在同一条教研记录上。列表和详情使用同一数据源，不允许分别计算或维护。

## 5. 流程节点与可操作范围

### 5.1 通用规则

- 当前节点可操作。
- 已完成节点可回看。
- 未到达节点置灰且不可点击。
- 后端必须再次校验当前状态，不允许只依赖前端禁用按钮。

### 5.2 管理端入口

| 页面入口 | 最早可用阶段 | 主要功能 |
|---|---|---|
| 教研主题 | 教研准备 | 查看主题、目标、活动方案、关联案例和素材 |
| 在线研讨 | 在线研讨 | 话题、回复、置顶、预设标识和研讨摘要 |
| 现场记录 | 现场记录 | 出勤、资料、录音、转写、AI 会议纪要 |
| 成果文件 | 成果沉淀 | 案例小结、教研总结、会议归档包 |

### 5.3 教师端入口

| 页面入口 | 最早可用阶段 | 权限 |
|---|---|---|
| 教研主题 | 教研准备 | 查看 |
| 在线研讨 | 在线研讨 | 加入、发表话题、回复、查看 |
| 成果文件 | 成果沉淀且成果已发布 | 查看、下载允许公开的成果 |

## 6. 功能需求

### 6.1 创建与编辑教研

#### FR-01 基础信息

- 教研主题：必填。
- 教研范围：园级、年级组、班级。
- 关联案例：支持一个教研关联多个案例。
- “主题依据”统一改名为“教研目标”。
- AI 助手可根据关联案例生成教研主题、教研目标和活动方案建议。

#### FR-02 活动方案与教研素材

- 保留研讨日期、研讨地点和研讨安排。
- 原附件上传区域改名为“上传教研素材”。
- 支持视频、文档、音频、图片及其他常用文件，前端不限制文件扩展名。
- 后端仍需执行文件大小、病毒扫描、内容安全和存储配额校验。
- 素材需记录文件名、MIME 类型、大小、上传人、上传时间和关联教研。

#### FR-03 参与设置

- 设置主持人和参与教师。
- 设置教师是否允许发表新话题、回复互动和匿名参与。
- 新增“管理员预设话题”。
- 预设话题字段包括关联范围、话题标题和讨论提示。
- 关联范围可选择整场教研或某个关联案例。
- 教研发布后，预设话题自动进入在线研讨并显示“管理员预设”标识。

### 6.2 在线研讨

#### FR-04 话题

- 一个教研主题包含多个话题。
- 一个话题必须关联整场教研或一个具体案例。
- 管理员和有权限的教师可发表话题。
- 管理员可置顶、取消置顶、关闭或隐藏不当话题。
- 话题显示作者、角色、时间、关联范围、正文和回复数。

#### FR-05 回复

- 一个话题包含多条回复。
- 有权限且已加入教研的教师可回复。
- 回复记录作者、时间、内容和所属话题。
- 发表话题或回复后，成员参与状态更新为“已参与”。

### 6.3 参与成员侧边栏

#### FR-06 成员入口

- “参与成员”不作为教研业务 Tab。
- 管理端和教师端均通过详情页右侧成员入口打开抽屉。
- 交互形态参考腾讯会议成员面板，不离开当前业务页面。

#### FR-07 成员信息

- 展示头像、姓名、班级、教研内角色和参与状态。
- 展示个人发表话题数和回复数。
- 普通教师当前用户显示“我”标识。
- 管理端可提醒待参与教师。

#### FR-08 活跃度

第一版使用可解释的规则计算：

`活跃分 = 话题数 × 3 + 回复数`

| 活跃分 | 标识 | 展示建议 |
|---:|---|---|
| 15 分及以上 | 高活跃 | 绿色 |
| 6-14 分 | 已参与 | 橙色 |
| 0-5 分 | 待参与 | 灰色 |

活跃度仅用于教研过程提示，不建议直接用于教师绩效评价。后续如加入点赞、被引用和有效回复质量，应由产品另行定义权重。

### 6.4 现场记录

#### FR-09 会议资料

- 实际召开时间。
- 实际出勤人数和缺席人数。
- 现场照片、视频、文档及其他附件。
- 现场录音。
- 录音转写稿。
- AI 会议纪要。

#### FR-10 录音转写

状态为：待上传、转写中、转写完成、转写失败。

- 录音上传后创建异步转写任务。
- 转写完成后保留完整文字稿及时间戳。
- 转写失败时允许重新提交。
- 未完成转写时，AI 会议纪要按钮不可用。

#### FR-11 AI 会议纪要

- 会议纪要不能从空白手工新建。
- 必须基于完整录音转写稿由 AI 生成。
- 生成状态为：待生成、生成中、已生成、生成失败。
- 生成结果使用 Markdown 存储。
- 建议结构包括会议结论、主要分歧、后续行动和责任人。
- AI 初稿生成后，主持人可编辑并保存版本。
- 系统需保留生成时间、使用的转写版本、最后编辑人和最后更新时间。
- 进入成果沉淀前，必须存在一份已生成并保存的会议纪要。

### 6.5 成果沉淀

#### FR-12 案例小结

- 每个关联案例独立生成一份案例小结。
- 小结输入包括案例材料、关联话题与回复、录音转写片段和会议纪要。
- 管理端可生成和编辑。
- 教师端只查看已发布版本。

#### FR-13 整次教研总结

- 必须在全部案例小结完成后生成。
- 输入包括全部案例小结、整场教研话题、会议纪要和成员参与记录。
- 管理端可生成和编辑。
- 教师端只查看已发布版本。

#### FR-14 本次会议归档

- 不再生成教研报告。
- 教研总结完成后，管理端可生成 ZIP 归档包。
- 归档完成后，教研状态更新为“已完成”，进度更新为 100%。
- 归档包建议结构如下：

```text
教研主题_日期.zip
├─ 01_教研准备
│  ├─ 教研主题与目标.md
│  ├─ 活动方案.md
│  └─ 教研素材
├─ 02_在线研讨
│  ├─ 话题与回复.json
│  └─ 参与成员.csv
├─ 03_现场记录
│  ├─ 现场图片
│  ├─ 现场视频
│  ├─ 现场录音
│  ├─ 录音转写稿.md
│  └─ AI会议纪要.md
└─ 04_成果文件
   ├─ 案例小结
   └─ 教研总结.md
```

## 7. 权限设计

权限按教研范围生效，并与教师平台角色、教研内角色和具体操作动作共同判断。

### 7.1 权限模型

建议后端采用四个维度组合鉴权：

1. 用户平台角色。
2. 教研范围。
3. 教研内角色。
4. 资源动作。

用户拥有案例教研权限，不代表拥有案例管理、统计、设置或其他园本教研功能权限。

### 7.2 教研范围

- 园级教研：授权到全园或指定园区。
- 年级组教研：授权到指定年级组。
- 班级教研：授权到指定班级。
- 主班老师可单独开通案例教研权限，并仅访问本人班级或被邀请的教研。
- 跨班、跨年级参与必须通过邀请名单或额外范围授权。

### 7.3 建议权限点

| 权限点 | 管理者/主持人 | 普通教师 |
|---|---:|---:|
| research.create | 是 | 否 |
| research.edit | 是 | 否 |
| research.publish | 是 | 否 |
| research.end | 是 | 否 |
| research.view | 是 | 按范围 |
| topic.create | 是 | 按设置 |
| topic.reply | 是 | 按设置 |
| topic.moderate | 是 | 否 |
| member.view | 是 | 是 |
| member.remind | 是 | 否 |
| record.manage | 是 | 否 |
| transcript.create | 是 | 否 |
| minutes.generate | 是 | 否 |
| minutes.edit | 是 | 否 |
| result.generate | 是 | 否 |
| result.view | 是 | 已发布后 |
| archive.create | 是 | 否 |
| archive.download | 是 | 按发布设置 |

### 7.4 后端校验要求

- 每个写接口必须校验权限点和教研范围。
- 每个状态变更接口必须校验当前状态和目标状态。
- 文件下载必须使用短时授权地址，不能只依赖前端隐藏。
- 话题、回复、纪要和成果编辑需记录操作日志。
- 权限变更后应及时失效缓存，避免越权访问。

## 10. 非功能需求

- 页面首次可交互时间建议不超过 3 秒。
- 话题列表和成员列表需要分页或虚拟滚动。
- 大文件使用分片上传、断点续传和失败重试。
- AI 任务需要幂等键，防止重复生成和重复计费。
- Markdown 内容需防止 XSS，展示时使用安全白名单渲染。
- 所有上传文件需要病毒扫描、内容安全检测和访问审计。
- 关键操作保留操作人、时间、前后状态和失败原因。
- 支持桌面端和手机端响应式布局。

## 11. 验收标准

1. 列表和详情均只显示四个阶段，状态和进度完全一致。
2. 在线研讨阶段，现场记录和成果文件置灰且不可点击。
3. 现场记录阶段，成果文件置灰且不可点击。
4. 教师端只显示教研主题、在线研讨和成果文件三个入口。
5. 教师端不显示创建、结束教研、现场资料编辑和成果生成按钮。
6. 参与设置可新增、查看和删除管理员预设话题。
7. 发布后的预设话题带“管理员预设”标识。
8. 参与成员通过右侧抽屉展示，不再出现在业务 Tab 中。
9. 成员抽屉显示头像、姓名、班级、话题数、回复数和活跃标识。
10. 未完成录音转写时，AI 生成会议纪要按钮不可用。
11. AI 会议纪要生成前不能手工输入；生成后可编辑 Markdown。
12. 未生成会议纪要时不能进入成果沉淀。
13. 全部案例小结完成前，教研总结按钮不可用。
14. 教研总结完成前，归档包按钮不可用。
15. 归档完成后状态为已完成、进度为 100%，不出现教研报告。
16. 活动方案下显示“上传教研素材”，支持多类文件。
17. 所有“主题依据”文案均改为“教研目标”。
18. 后端对越权写操作返回 403，对非法状态流转返回 409。

## 12. 本期不实现

- 将活跃度直接用于绩效考核。
- 实时音视频会议。
- 自动识别线下会议是否真正召开。
- 复杂的 AI 质量评分。
- 面向外部人员的公开社区。
- 教研报告生成。

## 13. 演示说明

当前演示为前端交互原型，不连接真实后端。弹窗、状态切换、录音转写、AI 纪要、成果生成和归档均使用本地模拟数据，用于确认产品流程和开发范围。
